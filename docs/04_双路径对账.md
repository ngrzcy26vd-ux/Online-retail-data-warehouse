## 二、两条路径各自怎么做的

### 路径一：pandas

```
read_csv → strip/upper → CustomerID 转 Int64 → line_amount
→ 建 8 个布尔标记列 → where 条件化金额 → groupby 聚合出 orders / customers
```

关键：用**穷举白名单** `FEE` 判费用类，用**逐条条件覆盖**判四类单据。

### 路径二：Hive SQL

只读 `stock_code / invoice_no / quantity / unit_price` 四个原始字段，
**不引用任何 pandas 派生的标记列和金额列**：

```sql
-- 四类（互斥，靠 CASE WHEN 重写判据）
cancel = invoice_no LIKE 'C%'
stock  = invoice_no NOT LIKE 'C%' AND quantity < 0
bad    = stock_code = 'B'
formal = invoice_no NOT LIKE 'C%' AND quantity >= 0 AND stock_code <> 'B'

-- 费用类（穷举白名单的 SQL 版，不用正则）
non_product = stock_code IN ('POST','DOT','M','C2','D','S','BANK CHARGES',
                             'AMAZONFEE','CRUK','B')
              OR stock_code LIKE 'GIFT_0001_%'

-- GMV 两口径
毛额 = SUM(CASE WHEN is_product AND is_formal THEN quantity*unit_price END)
净额 = SUM(CASE WHEN is_product AND (is_formal OR is_cancel) THEN quantity*unit_price END)
```

## 三、中途踩的坑：398.45 的教训（**最值得记的一条**）

第一版 SQL 我加了一个"看起来更严谨"的条件：

```sql
AND stock_code RLIKE '^[0-9]{5}[A-Z]{0,3}$'    -- ❌ 用正则判"是不是商品"
```

结果：毛额 10,246,820.87 / 净额 9,770,919.71，**比 pandas 少了 398.45**。

**398.45 正好等于 DCGS 系列 45 行的金额。** DCGS 和 PADS 的编码格式"不规矩"，但它们是真商品 —— 正则把它们当费用类剔掉了。

去掉正则、改成只用白名单的反面判断后，完全对上。

### 这条为什么值钱

1. **这个错我们一周前就在文档里写明了「不可用规则式判断，会误杀 DCGS/PADS，GMV 少 398.45」** —— 一周后写 SQL 时我自己又犯了。
2. **是差额反推救的场**：不盯着代码猜，先算差额（398.45），再看哪个东西的金额正好等于它。
3. **规则写在文档里不够，必须在实战中被咬一次**。

## 四、这个对账的强度（面试怎么说）

| 档位 | 做法 | 验证力度 |
|---|---|---|
| 一档 | Hive `SUM(orders.gross_amount)` | ⭐ 只能验证文件没传坏 |
| **二档（本次达成）** | Hive 从明细用 SQL **重写全部判定逻辑**再聚合 | ⭐⭐⭐⭐ 验证清洗规则本身 |
| 三档 | 原始 CSV 进 Hive，连 `TRIM/UPPER` 也用 SQL 重做 | ⭐⭐⭐⭐⭐ 再加验证归一 |

本次达到二档：数据用的是 pandas 归一后的结果，但**四类判定、费用白名单、GMV 口径全部在 SQL 里独立重写**，不引用任何 pandas 的派生列。

**面试可说的那句话**：

> 「我用 pandas 和 Hive SQL 写了两套完全独立的清洗逻辑——一套在 Python 里用布尔掩码和条件化金额，一套在 SQL 里用 CASE WHEN 从原始字段重判四类单据。两条路径独立算出 11 个指标，包括毛额 1,024 万、净额 977 万，逐项零差额。中途 SQL 版少了 398.45，反查发现是我在 SQL 里用正则判商品，误杀了 DCGS 系列的 45 行——改回穷举白名单后完全对上。」

## 五、200 字项目说明（可放文档/简历附件）

> 本项目对 UCI Online Retail 数据集（541,909 行，2010-12 ~ 2011-12，38 国）做端到端数据治理。清洗阶段识别四类互斥单据——正常单 526,051 行、取消单 9,251 行、库存记录 1,336 行、坏账 3 行，靠"编码前缀 + 数量符号 + 单价为零"三重证据判定，其中库存记录以单价 100% 为零、客户 ID 100% 缺失作为交叉验证。剔除 2,940 行费用类单据（邮费/折扣/手续费，用穷举白名单而非规则式判断，因为 DCGS/PADS 编码不规矩但属真商品）。归一处理商品编码大小写（消除 112 个重复编码）、国家名多写法、客户 ID 缺失（填 UNKNOWN 而非 0，避免污染客户层分析）。最终产出明细层 536,641 行、订单层 25,900 行、客户层 4,372 行三张表，毛额 GMV 1,024.72 万元、净额 977.13 万元（取消单冲销 −47.59 万元）。用 pandas 与 Hive SQL 两套独立逻辑重算 11 个指标，零差额。
