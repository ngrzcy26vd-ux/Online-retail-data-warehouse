源数据是驼峰（`InvoiceNo`），输出库表用下划线小写。**交付前必须改名**，一眼区分"原始数据"和"加工后数据"。

## 一、`retail_clean`（明细层）· 17 列 · 536,641 行

### 原始事实 8 列

| 字段 | 类型 | 含义 | 加工动作 |
|---|---|---|---|
| `invoice_no` | STRING | 订单号。`C` 开头=取消单，`A` 开头=调整单 | strip + upper |
| `stock_code` | STRING | 商品/费用编码。5 位数字+可选字母=真商品 | strip + upper |
| `description` | STRING | 商品名 | strip + title，缺失填 `未知商品` |
| `quantity` | INT | 数量。负数=业务事实（退货/库存），**不洗** | 无 |
| `invoice_date` | TIMESTAMP | 开票时间 | to_datetime |
| `unit_price` | DOUBLE | 单价。负值=坏账调整（仅 3 行），**不洗** | 无 |
| `customer_id` | STRING | 客户 ID。缺失填 `UNKNOWN`，**不填 0** | `Int64`→str，`<NA>`→`UNKNOWN` |
| `country` | STRING | 国家 | `EIRE`→`Ireland` |

### 派生金额 1 列

| 字段 | 类型 | 含义 | 公式 |
|---|---|---|---|
| `line_amount` | DOUBLE | 行金额（不是单金额） | `quantity * unit_price`，round 2 |

### 单据分类 4 列（**互斥**，四列相加 = 总行数）

| 字段 | 类型 | 行数 | 判据 |
|---|---|---|---|
| `is_formal` | BOOLEAN | **526,051** | 非下面三类 |
| `is_cancel` | BOOLEAN | **9,251** | `invoice_no` 以 C 开头 |
| `is_stock_record` | BOOLEAN | **1,336** | `quantity < 0` 且非 C 单 |
| `is_bad` | BOOLEAN | **3** | `stock_code = 'B'`（坏账，数量+1 单价−11,062.06） |

**守恒校验**：`526,051 + 9,251 + 1,336 + 3 = 536,641` ✅

### 业务标记 4 列（**可叠加**，不互斥）

| 字段 | 类型 | 行数 | 含义 |
|---|---|---|---|
| `is_return` | BOOLEAN | **10,587** | `quantity < 0`。= 取消 9,251 + 库存 1,336（完全相等，可交叉验证） |
| `is_zero_price` | BOOLEAN | **1,174** | `unit_price = 0` 且非库存记录 |
| `is_non_product` | BOOLEAN | **2,940** | 11 类费用白名单 + `GIFT_0001_` 前缀 |
| `is_product` | BOOLEAN | **533,701** | `is_non_product` 取反 |

**守恒校验**：`2,940 + 533,701 = 536,641` ✅

### 费用白名单（穷举，32 个非标准编码中的 2,940 行）


## 五、GMV 两口径定义

| 口径 | 公式 | 金额 |
|---|---|---|
| 毛额 | `is_product & is_formal` 的 `line_amount` 之和 | **10,247,219.32** |
| 净额 | `is_product & (is_formal \| is_cancel)` 的 `line_amount` 之和 | **9,771,318.16** |
| 冲销差额 | 净 − 毛 | **−475,901.16**（占毛额 −4.64%） |

两个口径结构完全同构：**同一批行、同一个金额列，只差一个 `| is_cancel`**。这是可解释性的来源。

### 旧数字 9,758,809.99 的去向

那是「原始 541,909 行 + 未剔费用类 + 正常单&取消」的旧口径，不是错数。全部差额可解释：

- `9,792,708.88 − 9,758,809.99 = 33,898.89` = 费用类落在该口径内的金额
- `9,792,708.88 − 9,771,318.16 = 21,390.72` = 去重删的 5,268 行落在这部分里的金额

## 七、Hive 建表风险提示

1. **BOM**：交付 CSV 用 `utf-8-sig`（Excel 友好），进 Hive 前必须去 BOM，否则列名变 `\ufeffinvoice_no`，SQL 静默查空。
2. **布尔列**：pandas 输出 `True`/`False`。Hive 若读成 NULL，改输出 `1`/`0` + 建表用 `TINYINT`。
3. **库名**：必须用 `retail_*`，**避开**已有的 `ods`/`dwd`/`dws`/`ads`（15 行教学数据）和 `dirty`（212 单）。
4. **`customer_id`**：含 `UNKNOWN` 字符串，类型必须 STRING，不能推成大整数。
