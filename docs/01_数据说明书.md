## 一、这是什么数据

| 项 | 值 |
|---|---|
| 来源 | UCI Machine Learning Repository，英国在线零售商真实交易 |
| 原始行数 | 541,909 |
| 去重后 | 536,641（删 5,268 行完全重复，占 0.97%） |
| 时间跨度 | 2010-12-01 08:26 ~ 2011-12-09 12:50，**373 天** |
| 国家数 | 38 |
| **粒度** | **一行 = 一个商品行**，不是一张单 |
| **主键** | **无单列主键**。25,900 单散成 536,641 行，单号必然重复 |

**粒度这一条是最容易被问倒的。** 55 万行看着像"55 万笔交易"，其实只有 2.59 万张单。

## 二、8 个字段：类型 + 关键事实

| 字段 | 类型 | 关键事实 |
|---|---|---|
| `InvoiceNo` | str | 6-7 位。**`C` 开头 = 取消单（9,251 行 / 3,836 单），`A` 开头 = 调整单（3 行坏账）**，数字开头 = 正常单 |
| `StockCode` | str | 商品/费用编码。**5 位数字 + 可选字母后缀 = 真商品（3,943 个）**；32 个非标准编码中 15 个是费用类、17 个是真商品（DCGS/PADS） |
| `Description` | str | 缺失 1,454 行；**前后带空格 112,371 行**；含 `?`(47) / `??`(7) 占位符；归一后唯一值 4,195 |
| `Quantity` | int | 范围 −80,995 ~ +80,995；负数 10,587 行（取消 9,251 + 库存 1,336）；**`\|Q\| > 10,000` 有 5 行** |
| `InvoiceDate` | object→datetime | **读进来是 object，必须 to_datetime**；无缺失 |
| `UnitPrice` | float | 范围 **−11,062.06 ~ 38,970**；`=0` 有 2,510 行；`<0` **只有 2 行**（坏账） |
| `CustomerID` | float→str | **缺失 24.93%（13.5 万行）**；4,372 个真实客户；因为是 float 所以显示 `17850.0` |
| `Country` | str | 38 个取值；**`EIRE` 8,184 行 = Ireland**，同一国家两种写法 |

## 三、三类偏差方向（核心，可以套任何表）

### 方向一：让数值偏大 / 偏小 —— 毁金额、均值

| 坑 | 规模 | 后果 |
|---|---|---|
| `UnitPrice = 0` | 2,510 行 | 金额算 0，GMV 被低估 |
| `UnitPrice < 0`（坏账） | 2 行，−11,062.06 | 直接减收入 |
| `Quantity` 极值 | 5 行，最大 80,995 | **总额无影响（两对正负抵消），但平均订单金额被拉爆** |

**要点：极值不影响总额，专毁平均值。** 所以查极值不是为了对总额，是为了知道哪些指标不能用。

### 方向二：让计数多算 / 少算 —— 毁订单数、客户数

| 坑 | 规模 | 后果 |
|---|---|---|
| 整行重复 | 5,268 行 | 行数虚高 0.97%，所有 count 偏大 |
| `CustomerID` 缺失 | 24.93% | `value_counts()` 默认**隐藏**它们，会以为没缺失 |
| `CustomerID` 填 0 | — | 造出假客户，Top-N 第一名永远是它 |
| `C` 开头单混入 | 9,251 行 | 取消单被算进销售额，收入虚高 |

### 方向三：让同一实体被拆开 —— 毁分组、Top-N（**不影响金额**）

| 坑 | 规模 | 后果 |
|---|---|---|
| `StockCode` 大小写 | **112 个编码重复**，1,977 行含小写 | `85123A` 2,301 行 + `85123a` 67 行 = 同一商品拆成两个 |
| `Country` 两种写法 | `EIRE` 8,184 行 | 爱尔兰拆成两行 |
| `Description` 前后空格 | 112,371 行 | 同一商品名被分成两类 |

**这一类最危险：金额一分不差，但所有按维度的分析全错。**

> **清洗不是为了金额对，是为了维度对。**

## 四、三种业务的符号长在三个不同地方

判业务看**编码/单号前缀**，判方向才看**符号**。两者独立。

| 业务 | 判据 | 符号在哪 | 规模 |
|---|---|---|---|
| 正常单 | 数字开头 | — | 526,051 行 |
| 取消单 | `C` 开头 | **数量**为负 | 9,251 行 |
| 库存记录 | 数量<0 且非 C | 数量为负，**单价全为 0** | 1,336 行 |
| 坏账 | `StockCode = 'B'` | **单价**为负 | 3 行（1 正 2 负，净 −11,062.06） |
| 赠品 | `UnitPrice = 0` | 无符号 | 1,157 行（商品口径） |

**坏账是唯一"数量 +1、符号长在单价上"的业务。** 只用 `Quantity < 0` 永远抓不到它。

## 五、面试怎么答（一段话模板）

> 「这是英国一家在线零售商 2010 年 12 月到 2011 年 12 月的真实交易数据，原始 54 万行，去重后 53.6 万行，覆盖 38 个国家、2.59 万张订单、4,372 个客户。
>
> 粒度是商品行级，不是订单级——55 万行对应 2.59 万单，平均一单 21 行。
>
> 数据有三类脏：一类是金额层面，单价有 2,510 行是 0（赠品）和 2 行负值（坏账）；一类是计数层面，客户 ID 缺失 25%，整行重复 5,268 行；还有一类最隐蔽，商品编码有 112 个大小写重复、国家名有 EIRE/Ireland 两种写法，**这一类的金额完全对得上，但按商品或国家做汇总会错**。
>
> 我最后定义了三个口径：毛额 GMV 1,024 万（只算正常单商品行）、净额 977 万（加上取消单冲销 −47.6 万）、以及客户层 826 万——差额 150 万正好是匿名客户贡献的。」

**这段话里有：时间、规模、粒度、三类问题、三个口径、以及差额的可解释性。** 说完这些，面试官会认为你真的做过，而不是拼了一个项目。

## 六、三个必须带口径的数字

| 指标 | 说法 |
|---|---|
| 取消单 | **9,251 行 / 3,836 单**。不能说"9,288"（那是原始行数） |
| 坏账 | **3 行**，其中 2 行负、1 行正，净 −11,062.06 |
| UNKNOWN 客户 | **3,710 张单**（全部）/ 2,172 张（含 GMV 的） |

**报数字时主语要完整。** 不说「负单价 2 行」，说「单价为负的有 2 行」。
